# Phase 04.1: edition edits - Context

**Gathered:** 2026-06-21
**Status:** Ready for planning

<domain>
## Phase Boundary

Transform the existing broadsheet edition into a realistic vintage newspaper front page — dynamically rendered from interview summary or daily tracking data, with authentic 2000-era broadsheet print texture effects and export to 17×11 PNG/PDF. This phase elevates the current `NewspaperLayout` component from a clean 4-column layout into a full newspaper simulation with halftone photos, paper grain, fold crease, ink bleed, and edge wear — all applied as inline SVG/CSS filters captured by the existing client-side `html-to-image` pipeline.

The newspaper is the primary output format for all carbon data: interview summaries (edition page), daily tracking stats (daily page), and shared snapshots (share page).

</domain>

<decisions>
## Implementation Decisions

### Realism Depth
- **D-45:** **Full scan simulation.** All layers applied: paper grain (feTurbulence + feColorMatrix), halftone dot pattern on images (SVG feColorMatrix filter), horizontal fold crease (gradient line + drop-shadow), subtle ink bleed on bold headlines, slight edge wear/deckled edges, and warm cream-to-ivory background gradient.
- **D-46:** **2000 broadsheet era calibration.** Bright-ish cream paper, clean print, subtle aging. No foxing spots, no extreme yellowing, no scanner artifacts. Based on the "Burlington Free Press" reference style.
- **D-47:** **All effects as inline SVG/CSS filters on DOM.** No separate canvas post-processing step. Effects render in the browser at render time and are captured natively by html-to-image.
- **D-48:** **Halftone via SVG feColorMatrix filter** applied to `<img>` elements. Renders at DOM level, captured by html-to-image without extra processing.
- **D-49:** **Paper grain via feTurbulence + feColorMatrix** SVG filter on the broadsheet container element.

### Data Sources & Routing
- **D-50:** **Single NewspaperLayout component** renders from any data source — interview summary, daily tracking stats, or both combined. One component, multiple data contexts.
- **D-51:** **Newspaper accessible on three routes:** edition page (`/edition/[sessionId]` — existing broadsheet toggle), daily page (`/daily` — new "View as Newspaper" button), and share page (`/share/[snapshotId]` — renders newspaper version of shared snapshot).
- **D-52:** **Adaptive layout.** Omit sections without data and reflow columns naturally. No empty placeholders or "No data yet" messages. The newspaper fills its column space with available content.

### Typography & Fonts
- **D-53:** **Playfair Display** for headlines (bold serif, high contrast, vintage newspaper feel) and **PT Serif** for body text (workhorse serif at 8-10pt, excellent readability). Both loaded via `next/font/google` with `display: 'block'` for reliable export capture. The `@supports` fallback stack: `'Playfair Display', 'Times New Roman', serif` for headlines; `'PT Serif', Georgia, serif` for body.

### Rendering & Export Pipeline
- **D-54:** **Client-side html-to-image retained.** No Puppeteer, no server-side rendering infrastructure. The existing `toPng` pipeline from `html-to-image` handles all export.
- **D-55:** **Inline SVG filters captured natively.** All vintage effects (grain, halftone, fold crease, ink bleed, edge vignette) are SVG/CSS filters on DOM elements — html-to-image captures them directly in the PNG output. No post-capture canvas manipulation.
- **D-56:** **17×11 broadsheet landscape.** Export dimensions match true broadsheet proportions. PDF layout uses jsPDF with `[279.4, 431.8]` mm format (existing pattern).
- **D-57:** **No post-capture processing.** Inline filters alone are sufficient for the 2000 broadsheet look. No rotation, no additional canvas passes.

### the agent's Discretion
- The agent decides the specific SVG filter parameter values (turbulence frequency, color matrix values, halftone dot size/LPI, fold crease shadow intensity) — tuning these for visual quality is implementation detail.
- Exact column count distribution (4-6 columns) can be decided based on content density at render time.
- The masthead title ("Calm Carbon Report" vs. something more newspaper-like) is open to agent creativity, matching 2000 broadsheet convention.

</decisions>

## Existing Code Insights

### Reusable Assets
- `NewspaperLayout.tsx` (727 lines) — Existing broadsheet component with 4-column CSS layout, `column-span: all` masthead, category table, streak stats, pull quotes, and `forwardRef`/`useImperativeHandle` export API. Major refactor target for this phase.
- `html-to-image` (`toPng`) — Already used in both edition page and NewspaperLayout for PNG/PDF export. Zero new dependencies needed for export.
- `jsPDF` — Already used for PDF export. Landscape `[279.4, 431.8]` format already configured.
- `next/font` — Next.js built-in font optimization. Add Playfair Display and PT Serif via existing font loading pattern.

### Established Patterns
- **Imperative export API:** `forwardRef` + `useImperativeHandle` exposes `exportAsPNG()` / `exportAsPDF()` on `NewspaperLayoutHandle`. Keep this pattern.
- **View mode toggle:** edition page uses `ViewMode` state (`"standard" | "broadsheet"`) with tab-style toggle buttons. Extend to daily page.
- **CSS columns with `@supports` fallback:** Multi-column layout with flexbox fallback. Keep the progressive enhancement approach.
- **`<style jsx global>` for component styles:** All broadsheet styles live inside `<style jsx global>` in the component. Keep this for scoped styling.

### Integration Points
- **Edition page** (`edition/[sessionId]/page.tsx`) — Passes interview data as props to NewspaperLayout. Needs no structural changes for the new realism effects (they're internal to NewspaperLayout).
- **Daily page** (`daily/page.tsx`) — Needs new "View as Newspaper" button and NewspaperLayout render with daily data.
- **Share page** (`share/[snapshotId]/page.tsx`) — Needs NewspaperLayout render for shared snapshots.
- **Backend edition API** (`backend/app/api/edition.py`) — Data contract unchanged. Frontend already receives all needed fields (footprint, breakdown, quotes, benchmarks, insights).

</code_context>

<specifics>
## Specific Ideas

- The user provided a detailed 6-section spec sheet covering layout structure, typography, paper/print texture effects, color/age calibration by era, a suggested image generation prompt, and an HTML/CSS + code approach recommendation. This spec is the definitive design document for this phase.
- Reference images: The Winonan (2000s campus paper), Burlington Free Press (2000 broadsheet), 1980s East Village newspaper.
- All vintage effects should be SVG/CSS filter chains composable in CSS — no canvas post-processing.
- The newspaper should look like a scan of a real printed page, not a CSS approximation of one.

</specifics>

<deferred>
## Deferred Ideas

- **User-selectable era picker** — Letting users choose 1990s tabloid vs. 2000 broadsheet vs. 2008 campus as a dropdown. Deferred: adds UX complexity without clear user demand.
- **Multiple export sizes** — Supporting both 17×11 broadsheet and 11×8.5 tabloid export. Deferred: 17×11 meets the primary use case.
- **Scanner/photocopy artifacts** — Slight skew, faint scanner shadow. Deferred: 2000 broadsheet era is cleaner, these are unnecessary.
- **Foxing/age spots** — Brownish-yellow spots for older clippings. Deferred: 2000 broadsheet era doesn't need aging artifacts.

</deferred>
